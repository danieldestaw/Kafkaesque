Dashboard

Real-time overview of your Kafka ecosystem.

The dashboard is the default landing page after login. It requires an active cluster selection and pulls live data from the cluster health, topics, consumer groups, and audit APIs — refreshing every 30 seconds automatically.

Layout

Row 1 — KPI cards

CardSourceDetails
BrokersCluster healthOnline broker count with sparkline
TopicsCluster health + topics APIActive (non-internal) topic count
PartitionsCluster healthTotal partition count
Consumer GroupsCluster healthActive group count
Under-ReplicatedCluster healthPartitions needing attention
Offline PartitionsCluster healthCritical partition count

Row 2 — Metrics & health

  • Cluster Metrics — Multi-series area chart tracking brokers, topics, partitions, and consumer groups over the last 30 minutes. History builds from live health polls.
  • Cluster Health — Donut gauge with shield icon, status label (HEALTHY / degraded), and checklist: brokers online, partitions healthy, replication %, disk usage. Link to brokers page.

Row 3 — Insights

  • Top Topics by Messages — Donut chart ranked by partition count with percentage legend. Link to topics page.
  • Recent Activity — Last five audit log entries with timestamps and SUCCESS/INFO badges. Link to audit page.
  • Cluster Load — Three progress bars:
    • Partition density — partitions per broker (e.g. 83% · 83 partitions / broker)
    • Consumer lag — derived from total lag across groups
    • Replication stress — under-replication indicator
    Link to consumer groups page.

Refresh control

The header shows Last updated: just now with a refresh button. Clicking it invalidates all dashboard queries and reloads data immediately.

Sidebar widgets

  • Cluster Status — Green indicator when cluster health is HEALTHY
  • User profile — Avatar, display name, and role at the bottom of the sidebar
All dashboard metrics come from live API responses. No mock or placeholder data is shown when a cluster is connected.

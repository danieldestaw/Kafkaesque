RBAC & IAM

Database-backed roles, permissions, and user lifecycle management.

Overview

Kafkaesque uses role-based access control enforced on every API route. Roles and permissions are stored in PostgreSQL — not hardcoded in the frontend — so administrators can create custom roles and adjust permission matrices through the UI.

Default roles

RoleDescriptionSystem role
ADMINFull platform access including users and rolesYes
OPERATORManage Kafka infrastructure; no user/role adminYes
DEVELOPERInspect clusters, browse/publish messages, create topicsYes
VIEWERRead-only access to Kafka resources and auditYes

System roles can be renamed and have permissions edited, but cannot be deleted.

User management

Administrators can manage users from Administration → Users:

  • Create users with email, display name, role, and password
  • Edit user profile, role, and active status
  • Disable / enable accounts
  • Reset passwords (admin-initiated)
  • Revoke all active sessions (increments token_version)
  • View per-user audit history

Session security

  • JWT tokens include token_version claim
  • Revoking sessions increments the user's version — old tokens are rejected
  • Password changes can invalidate existing sessions
  • Login attempts (success and failure) are audit-logged

Role editor

From Administration → Roles, admins can create custom roles with a permission matrix loaded from GET /api/v1/permissions. Changes persist immediately to PostgreSQL and apply on the next API request.

Frontend enforcement

  • AdminRoute — guards admin pages by permission
  • PermissionGuard — conditionally renders UI elements
  • Navigation items filtered by user's effective permissions
